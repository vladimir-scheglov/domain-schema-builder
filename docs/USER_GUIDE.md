- **URL локально:** http://localhost:5173
- **Требования:** Node.js ≥ 20

## Первый запуск

### Локально

```bash
# В корне проекта
npm install
npm run build

# В папке web
cd web
npm install
npm run dev
```

Откроется http://localhost:5173.

### Что вы увидите

```
┌──────────────────────────────────────────────────────────┐
│ Toolbar (Примеры, Загрузить, …, Сгенерировать, ?)        │
├──────────┬─────────────────────────────┬─────────────────┤
│ Сущности │ Редактор                    │ Предпросмотр    │
│          │  - Домен                    │  DSL | Схема    │
│  +       │  - <выбранная сущность>     │  | Изменения    │
│          │  - Перечисления             │                 │
│          │  - Workflow                 │                 │
│          │  - Связи                    │                 │
│          │  - Деревья                  │                 │
│          │  - Меню                     │                 │
└──────────┴─────────────────────────────┴─────────────────┘
```

### С чего начать

**Вариант A.** Нажмите **«Примеры ▾»** → выберите готовый пресет (IOCs, Аудит, Активы, Инциденты, Задачи).

**Вариант B.** Начните с чистого листа:
1. Заполните домен.
2. Добавьте первую сущность (**N**).
3. Заполните атрибуты (**A**).
4. Добавьте связь.
5. Отметьте в меню.
6. Скачайте DSL или сгенерируйте схему.

### Где посмотреть справку

Нажмите **?** или **F1** — откроется модалка со всеми горячими клавишами.

## Обзор интерфейса

### Тулбар

| Кнопка | Что делает |
|---|---|
| **?** | Открыть справку по горячим клавишам |
| **Примеры ▾** | Встроенные и пользовательские пресеты |
| **Загрузить DSL** | Загрузить `.dsl.yaml` из файла или вставить текст |
| **Очистить** | Сбросить редактор и удалить черновик |
| **Копировать DSL** | Скопировать текущий DSL в буфер |
| **Скачать DSL** | Скачать текущий DSL как `.dsl.yaml` |
| **Поделиться** | Скопировать ссылку с закодированным состоянием |
| **Сгенерировать YAML** | Прогнать через генератор и скачать `.schema.yaml` |

Справа от заголовка — индикатор **💾 Сохранено HH:MM:SS**.

### Левая панель — Сущности

Список всех сущностей домена. Клик — открывает в редакторе.

- **+** — добавить новую сущность.
- **⧉** — дублировать сущность (появляется при наведении).
- **×** — удалить (появляется при наведении).

### Центральная панель — Редактор

Секции сверху вниз:

1. **Домен** — метаданные.
2. **Сущность** (если выбрана) — имя, label, наследование, атрибуты, флаги генерации UI.
3. **Перечисления** — enum'ы.
4. **Workflow** — рабочие процессы.
5. **Связи** — связи между сущностями.
6. **Деревья** — иерархические связи.
7. **Меню** — какие сущности показывать в меню.

### Правая панель — Предпросмотр

Три режима:

- **DSL** — то, что получится при «Скачать DSL». Редактируемый текст.
- **Схема** — результат генератора.
- **Изменения** — семантический diff с применённым состоянием.

## Палитра команд

Нажмите **Cmd/Ctrl + K** — откроется окно быстрого поиска и выполнения команд.

### Что можно делать

- **Создать** — сущность, enum, workflow, дерево.
- **Действия с выбранной сущностью** — дублировать, добавить атрибут.
- **Перейти к** — сущность, enum.

### Как пользоваться

1. Нажмите **Cmd/Ctrl + K**.
2. Начните печатать название команды или сущности.
3. Список фильтруется.
4. **↑↓** — навигация, **Enter** — выполнить, **Esc** — закрыть.

### Пример

Наберите `new` — увидите все команды создания:

```
СОЗДАТЬ
  Новая сущность
  Новый enum
  Новый workflow
  Новое дерево
```

Наберите `incident` — увидите переходы и действия, связанные с инцидентом.

Секция **Домен** — первая на центральной панели.

| Поле | Обязательное | Что это |
|---|---|---|
| **ID (FQDN)** | ✅ | Уникальный идентификатор домена, типа `iocs.test` |
| **Версия** | ✅ | SemVer: `0.0.1`, `1.2.3` |
| **Название** | | Отображается в меню и заголовках |
| **Автор** | | Имя и контакт |
| **Описание** | | Что за домен |
| **Теги** | | Через запятую: `iocs, security` |

**Совет:** ID домена — как домен второго уровня: `iocs.test`, `audit.company.com`.

## Сущности

### Добавить сущность

**Способ 1:** клавиша **N**.

**Способ 2:** кнопка **+** в левой панели.

**Способ 3:** **Cmd/Ctrl + K** → «Новая сущность».

Редактор переключится на новую сущность. Заполните:

- **ID** — PascalCase: `Ioc`, `Incident`, `IocSource`.
- **Название** — человекочитаемое.
- **Label** — шаблон отображаемого имени.
- **Inherits** — ID родительской сущности.
- **Описание**.

### Поле Label

Шаблон для отображения объекта:

```
{type}: {value}          →  IP: 192.0.2.15
{incidentSubject}        →  Утечка данных
Источник {sourceName}    →  Источник VirusTotal
```

### Поле Inherits (Наследование)

Потомок наследует label, атрибуты, правила данных, действия.

```
Device (hostname, ipAddress)
 ├── Server (cpuCount, ramGb)
 └── Workstation (monitorSize)
```

**Ограничения:** только один родитель, без циклов, родитель может быть в другом домене (через FQID).

### Клонирование сущности

- Клавиша **Cmd/Ctrl + D** — дублировать выбранную.
- Или кнопка **⧉** в списке сущностей.

Создаётся копия с ID `<OriginalId>Copy`, `<OriginalId>Copy2`, …

**Что копируется:** атрибуты, label, description, inherits, флаги генерации UI.
**Что не копируется:** связи, пункт меню.

### Удалить сущность

**×** в списке. Подтверждение.

Удаление также удаляет: атрибуты, связи, пункт меню.

## Генерация UI для сущности

Под атрибутами — секция **«Генерация UI»** с четырьмя чекбоксами:

| Чекбокс | По умолчанию | Что генерирует |
|---|---|---|
| **Список** | ✅ включён | Списочное представление `lists_<entity>` |
| **Модальные окна** | ✅ включён | Формы создания и редактирования |
| **Панель просмотра** | ✅ включён | Боковая панель с деталями |
| **Полноэкранная карточка** | ❌ выключен | Карточка `pages_info<entity>` на весь экран |

### Зачем это нужно

**Отключить список:** для сущностей-справочников, которые появляются только в `Reference`. Не нужен отдельный экран со списком.

**Отключить модалки:** если создание/редактирование происходит через плейбуки или автоматизацию.

**Отключить панель:** если сущность не имеет детального просмотра.

**Включить полный экран:** для больших форм с множеством атрибутов и вкладок.

### Как это сохраняется

Флаги записываются в DSL в секцию `ui:`:

```yaml
entities:
  Ioc:
    name: Индикатор
    ui:
      list: false
      page: true
    attributes:
      value: String
```

**Правило:** пишутся только флаги, **отличающиеся от дефолтных**.

- `list: false` — потому что дефолт `true`.
- `page: true` — потому что дефолт `false`.
- Если все флаги дефолтные — секции `ui:` нет.

Это значит: **флаги сохраняются** при скачивании DSL, при сохранении пресета, при share-ссылке.

## Атрибуты

### Добавить атрибут

- Клавиша **A** (у выбранной сущности).
- Кнопка **+ Атрибут** в секции.
- Кнопка **+ Списком** для массового добавления.

### Поля атрибута

| Поле | Обяз. | Описание |
|---|---|---|
| **id** | ✅ | camelCase: `value`, `updatedAt`, `iocId` |
| **Название** | | Отображаемое имя |
| **Тип** | ✅ | Тип данных |
| **default** | | Значение по умолчанию |
| **readonly** | | Только для чтения после создания |

### Типы данных

**Базовые:** `String`, `Text`, `Integer`, `Decimal`, `Float`, `Bool`, `Date`, `Time`, `Timestamp`, `Uuid`, `MAC`, `IpAddress`, `CIDR`, `URL`, `Attachment`, `Identifier`.

**Пользовательские:** `enum(IocType)`, `workflow(IncidentWorkflow)`.

**Массивы:** `Array<String>`, `Array<Reference(User)>`, `Array<enum(IocType)>`.

**Ссылки:** `Reference(User)`.

### Поле readonly

**☑ включён** — атрибут доступен только при создании. В форме редактирования его нет.

Пример: `externalId` из внешней системы.

### Поле default

Подставляется, если пользователь не заполнил поле:

```
status    enum(IncidentStatus)    default: OPEN
priority  enum(Priority)          default: MEDIUM
```

Работает для: `String`, `Text`, `Integer`, `Decimal`, `Float`, `Bool`, `Date`, `Time`, `Timestamp`, `Enum`.

**Не работает** для: `Attachment`, `Identifier`, `Counter`, `Reference`, `Workflow`.

### Массовое добавление

Кнопка **+ Списком** открывает модалку с двумя колонками:

- **Слева** — textarea для ввода.
- **Справа** — живой предпросмотр.

**Формат строк:**

```
title: String
description: Text
status: enum(Status) : Статус
priority: enum(Priority) : Приоритет
externalId: String : Внешний ID : readonly
```

Правила:
- `id: type` — минимум.
- `id: type : Название` — с русским именем.
- `id: type : Название : readonly` — с флагом.
- `# комментарий` — игнорируется.
- Пустые строки — игнорируются.

**Конфликты:** если ID уже существует, строка подсвечивается красным, кнопка «Добавить» блокируется.

## Перечисления (Enum)

### Создать enum

- Клавиша **E**.
- Или кнопка **+** в секции «Перечисления».

### Формат значений

```
[id]              [Значения]
IncidentStatus    OPEN: Открыт
                  IN_PROGRESS: В работе
                  CLOSED: Закрыт
```

Одна строка — одно значение:
- `OPEN` — только id.
- `OPEN: Открыт` — id + отображаемое имя.

### Использование

В атрибуте выберите тип `enum(IncidentStatus)`.

## Связи

### Добавить связь

Кнопка **+** в секции «Связи».

### Типы

| Тип | Смысл | Пример |
|---|---|---|
| `1:1` | Один к одному | Пользователь ↔ Паспорт |
| `1:n` | Один ко многим | Пользователь → Учётные записи |
| `n:n` | Многие ко многим | Инцидент ↔ Индикатор |

### Направление

- **☑ ненаправленная** — обе стороны равнозначны. Для `n:n`.
- **☐ направленная** — от `От` к `К`. Для `1:n` и `1:1`.

### Кросс-доменные связи

Ссылка на сущность в другом домене: `dictionaries.test/IncidentCategoryDict`.

## Деревья

### Что такое деревья

Деревья позволяют отображать иерархическую структуру — например, `RiskAssessment > RiskCategory > Risk`.

### Добавить дерево

- Клавиша **T**.
- Или кнопка **+** в секции «Деревья».

### Поля

| Поле | Обяз. | Описание |
|---|---|---|
| **ID** | ✅ | Уникальный ID дерева |
| **Тип** | | `ordinary` (по умолчанию), `orderable`, `multiparent` |
| **Цепочка** | ✅ | Сущности через `>` |

### Синтаксис цепочки

```
RiskAssessment > RiskCategory > Risk
```

Если между двумя сущностями **несколько** связей — укажите явно:

```
RiskAssessment >(RiskAssessment_RiskCategory) RiskCategory >(RiskCategory_Risk) Risk
```

### Живое превью

Под полем цепочки — список сущностей с подсветкой:
- **Зелёный** — сущность найдена.
- **Красный** — не найдена.

### Что генерируется

Из одной строки DSL:

```yaml
trees:
  RiskTree: RiskAssessment > RiskCategory > Risk
```

Генерируется:
- Блок `trees` в схеме.
- Представление `tree_RiskTree` (тип `tree`, `variant: merged`).
- Автоматический пункт меню.
- Автогенерация связей при создании узлов.

## Меню

Секция **Меню** определяет, какие сущности появятся в меню системы.

### Как работает

1. Поставьте галочку напротив сущностей.
2. При генерации создаётся корневая группа и пункты для каждой отмеченной.
3. **Автоматически** добавляются пункты для всех деревьев.

### Снятие галочки

Сущность остаётся в домене, но в меню не появится. Полезно для вспомогательных сущностей.

## Предпросмотр и генерация

### Вкладка DSL

Обновляется **мгновенно** при любом изменении. Это **редактируемое** поле — изменения в DSL применяются к state через дебаунс.

### Вкладка Схема

Результат генератора. Обновляется по кнопке **↻** или при переключении на вкладку. Кнопка **📋** — копировать в буфер.

### Вкладка Изменения

Семантический diff. Показывает, что изменится в схеме с момента последнего применения.

- **+ зелёный** — добавлено.
- **− красный** — удалено.
- **~ жёлтый** — изменено.

Клик по элементу — переход к нему в DSL-редакторе.

## DSL-редактор

Кнопка **⛶** в тулбаре панели DSL (или **Cmd/Ctrl + E**) открывает **расширенный редактор**.

### Возможности

- **Подсветка синтаксиса YAML.**
- **Автодополнение** — типы, ID сущностей, enum'ов.
- **Emmet-подобные сниппеты** (Tab):
  ```
  ent:Ioc > title:String, value:String
  enum:Priority > LOW:Низкий, MEDIUM:Средний
  wf:TaskWorkflow > todo -> inProgress -> done
  link:Ioc > n:n > Incident
  tree:RiskTree > A > B > C
  ```
- **Hover-подсказки** — при наведении на сущность показывает её атрибуты, связи; на enum — значения; на workflow — статусы.
- **Валидация в реальном времени** — маркеры ошибок в gutter.
- **Панель схемы** — генерировать YAML прямо в модалке (кнопка **Схема**).
- **Diff** — семантический diff с применённым состоянием (кнопка **Изменения** или **Cmd+Shift+D**).

### Кнопки тулбара модалки

- **Схема** — открыть/закрыть панель сгенерированной схемы.
- **Изменения** — открыть/закрыть панель diff.
- **Форматировать** — нормализовать порядок ключей и отступы.
- **Отмена** — закрыть модалку (с проверкой на несохранённые изменения).
- **Применить** — применить изменения к state и закрыть (Cmd+Enter).

### Горячие клавиши в модалке

| Клавиша | Действие |
|---|---|
| **Tab** | Развернуть Emmet-аббревиатуру |
| **Cmd+Enter** | Применить |
| **Cmd+S** | Применить и закрыть |
| **Cmd+Shift+S** | Открыть панель схемы |
| **Cmd+Shift+D** | Открыть diff |
| **Esc** | Закрыть |

## Пресеты

Пресет — готовый пример домена. Бывает **встроенный** или **пользовательский**.

### Встроенные пресеты (14 штук)

**Стартовые:**
- **Пустой домен** — минимальный каркас.
- **CRUD-сущность** — все типовые поля.
- **Справочник** — классификатор.

**Предметные области:**
- **IOCs Domain** — индикаторы компрометации.
- **Активы** — оборудование с наследованием.
- **Инциденты** — workflow на 7 статусов.
- **Аудит** — два workflow.
- **Задачи** — канбан-подобный домен.

**Workflow:**
- **Линейный** — 3 статуса.
- **С ветвлением** — согласование.
- **Циклический** — с возвратами.

**Продвинутые:**
- **Наследование** — типы документов.
- **Кросс-доменные ссылки.**
- **Многие-ко-многим.**
- **Дерево** — иерархия.

### Пользовательские пресеты

Сохранить текущее состояние:

1. **Примеры ▾** → **＋ Сохранить текущее как пресет**.
2. Имя и описание.
3. Сохранить.

Пресет появится в секции **Мои пресеты**.

Действия:
- **Клик** — загрузить.
- **↓** — экспортировать в JSON.
- **×** — удалить.

### Импорт пресета

**Примеры ▾** → **↥ Импортировать из файла** → выберите `.preset.json`.

### Где хранятся

В `localStorage`, ключ `dsb.userPresets.v1`.

## Автосохранение

Редактор автосохраняет **рабочую сессию** каждые 500 мс после изменения.

### Индикатор

Справа от заголовка: **💾 Сохранено HH:MM:SS**.

### Где хранится

`localStorage`, ключ `dsb.draft.v1`. Один черновик на браузер.

### Восстановление

- **F5** — восстанавливается.
- **Закрытие и открытие вкладки** — восстанавливается.
- **Закрытие браузера** — восстанавливается.

### Очистить

Кнопка **Очистить** в тулбаре:
1. Подтверждение.
2. Удаление черновика.
3. Сброс редактора.

## Share-ссылки

### Как поделиться

1. Настройте домен.
2. **Поделиться**.
3. Ссылка скопируется.

Коллега открывает ссылку — видит ту же схему.

### Прямые ссылки на пресеты

```
http://localhost:5173/?preset=iocs
http://localhost:5173/?preset=audit
http://localhost:5173/?preset=tasks
```

### Ограничения

- **Длина ссылки.** Для больших доменов может превысить 2000 символов.
- **Не сохраняется на сервере.** Ссылка содержит всё внутри себя.

## Частые сценарии

### Создать новую сущность с нуля

1. **N** — создать сущность.
2. Заполнить ID (`Ioc`) и название.
3. **A** — добавить атрибут.
4. Заполнить поля.
5. Повторить для остальных атрибутов.
6. Проверить **Схему** справа.

### Скопировать сущность

1. Выбрать сущность.
2. **Cmd/Ctrl + D**.
3. Переименовать ID и name.

### Массово добавить атрибуты

1. **+ Списком**.
2. Вставить список:
   ```
   title: String
   description: Text
   status: enum(Status)
   ```
3. Проверить предпросмотр.
4. **Добавить**.

### Отключить генерацию списка у справочника

1. Открыть сущность.
2. В секции «Генерация UI» снять галочку **Список**.
3. Скачать DSL — увидеть секцию `ui: list: false`.
4. Сгенерировать схему — `lists_<entity>` отсутствует.

### Создать дерево

1. Создать три сущности: `Root`, `Middle`, `Leaf`.
2. Создать связи `Root → Middle` и `Middle → Leaf`.
3. **T** — создать дерево.
4. Ввести цепочку: `Root > Middle > Leaf`.
5. Проверить превью.
6. В меню появится пункт «Дерево Root».

### Поделиться схемой

**Быстро:** **Поделиться** — отправьте ссылку.

**Надёжно:** **Скачать DSL** — отправьте файл.

### Открыть в расширенном редакторе

1. **Cmd/Ctrl + E** или кнопка **⛶**.
2. Открывается модалка с CodeMirror.
3. Работать с подсветкой и автодополнением.
4. **Cmd+Enter** — применить.

### Посмотреть diff перед применением

1. Внести изменения в DSL.
2. В модалке — **Изменения** или **Cmd+Shift+D**.
3. Просмотреть список: `+ Entity`, `~ Attribute`, `− Linkage`.
4. Клик по элементу — переход к нему в DSL.
5. Применить.

### Быстро найти команду

1. **Cmd/Ctrl + K**.
2. Набрать `new` или `duplicate` или `incident`.
3. **Enter**.

## Troubleshooting

### «Загрузка пресета не срабатывает»

Откройте DevTools → Console. Если ошибка парсинга YAML — сообщите.

Проверьте, что `npm run build` в корне проекта выполнен (web использует собранный `dist`).

### «Автосохранение не работает»

Проверьте:
1. DevTools → Application → Local Storage — есть ли ключ `dsb.draft.v1`?
2. Не включён ли приватный режим?
3. Не переполнено ли хранилище?

### «Поделиться даёт слишком длинную ссылку»

- **Скачать DSL** и отправить файл.
- **Сохранить как пресет** и экспортировать JSON.

### «DSL, сгенерированный через web-UI, не принимается системой»

1. Проверьте вкладку **Схема** — ошибки покажутся под панелью.
2. Сравните с выводом CLI:
   ```bash
   npx tsx src/cli.ts gen examples/iocs.dsl.yaml
   ```

### «Горячие клавиши не работают»

1. Фокус в поле ввода — одиночные клавиши игнорируются. Кликните на пустое место.
2. Открыта модалка (DSL-редактор, палитра, справка) — хоткеи отключены.
3. Проверьте раскладку — `N` работает и на русской, и на английской.

### «Cmd+K не открывает палитру»

- **Cmd+K** = `Cmd` + `K`. На Windows/Linux — `Ctrl+K`.
- Если открыт DSL-редактор — хоткей отключён. Закройте модалку.

### «Cmd+D открывает закладку браузера»

Обновите страницу (Cmd+Shift+R). Хоткей должен блокировать дефолтное поведение браузера.

### «Элемент diff не подсвечивает строку в DSL»

- Некоторые элементы (linkage, action, view) не имеют **точного** соответствия в DSL. Подсветка — эвристика.
- Клик по **сущности** и **атрибуту** работает точно.

### «Граф workflow не рисуется»

1. Проверьте, что заполнены `statuses`.
2. Проверьте `initial`.
3. Если статусов много — используйте горизонтальный скролл.

### «После изменения ядра web показывает старую схему»

Пересоберите ядро:
```bash
npm run build
```
И перезагрузите web (Cmd+Shift+R).

### «Emmet не разворачивается по Tab»

1. Строка должна начинаться с `ent:`, `enum:`, `wf:`, `link:`, `tree:`, `menu:`, `ref:`, `arr:`, `arrRef:`.
2. Строка **подсвечена жёлтым** — значит распознана.
3. Если фокус потерян — кликните в конец строки.
